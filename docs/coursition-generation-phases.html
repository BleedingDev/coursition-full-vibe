Coursition generation phases

Dokumentace presne popisuje aktualni volani Ax po fazich, kde se uklada stav a proc full-auto i semi-auto pouzivaji stejnou znovupouzitelnou generaci aktivit.

Zadne legacy odpovedi Originalni soubory ani binarni obsah requestu se neposilaji zpet jako soucast workflow odpovedi.
Zadne fallbacky Nevalidni Ax vystup se odmitne nebo ulozi jako failed/not_playable, nikdy se nevymysli nahradni kurz.
Jazyk ridi Ax Pri languagePreference=source vybere coursePlanner hodnotu outputLanguage z dokumentu.

Jedna sada fazi

flowchart TD
  A[User action] --> B{Workflow action}
  B -->|Full-auto generateCourse| C[runLearningPlanPhase]
  B -->|Semi-auto generateLearningBlueprint| C
  C --> D[generateLearningPlanWithAi]
  D --> E[coursitionActivityGenerationFlow]
  E --> F[coursePlanner Ax node]
  F --> G[outputLanguage + coursePreparationJson + objectivesJson]
  G --> H[activityBriefPlanner Ax node]
  H --> I[activityBriefsJson]
  I --> J[(save draft: preparation + objectives + briefs)]
  J --> K{Next action}
  K -->|Full-auto continues| L[runActivityPhase]
  K -->|Semi-auto generateActivities| L
  L --> M[pendingActivityBriefs]
  M --> N[generateActivityWithAi for each brief]
  N --> O[coursitionPlayableActivityFlow]
  O --> P[playableActivityWriter Ax node]
  P --> Q[activityQualityJudge Ax node]
  Q --> R{quality passed?}
  R -->|yes| S[(save generated activity)]
  R -->|no / invalid| T[(save failed not_playable activity)]
  S --> U{all briefs covered?}
  T --> U
  U -->|yes| V[runCourseContentPhase]
  U -->|no| W[block courseContent gate]
  V --> X[generateCourseContentWithAi]
  X --> Y[(save course content)]
  Y --> Z[preview]
Stejne Ax aktivity: full-auto i semi-auto vstupuji do stejne funkce runActivityPhase a ta vola stejnou provider funkci generateActivityWithAi. Neexistuje druha paralelni generace aktivit pro full-auto.

Semi-auto sekvence

sequenceDiagram
  autonumber
  participant UI as UI step buttons
  participant Store as server/coursition/store.ts
  participant Plan as generateLearningPlanWithAi
  participant Act as generateActivityWithAi
  participant Content as generateCourseContentWithAi
  participant DB as draft store

  UI->>Store: generateLearningBlueprint
  Store->>Plan: runLearningPlanPhase(force=true)
  Plan-->>Store: preparation + objectives + briefs
  Store->>DB: save activityPlan-ready draft
  Store-->>UI: editable plan

  UI->>Store: generateActivities
  Store->>Act: runActivityPhase(ownerId, draft)
  par every pending brief
    Act->>Act: same coursitionPlayableActivityFlow
    Act-->>Store: generated or failed activity
    Store->>DB: save that activity before waiting for others
  end
  Store-->>UI: same draft shape as full-auto activity phase

  UI->>Store: generateCourseContent
  Store->>Store: getWorkflowStepGate("courseContent")
  Store->>Content: runCourseContentPhase(draft)
  Content-->>Store: sections rendered from saved activities
  Store->>DB: save content
  Store-->>UI: preview-capable draft

Resume a skip logika

flowchart LR
  A[Load latest draft] --> B{needsLearningPlan?}
  B -->|yes| C[runLearningPlanPhase]
  B -->|no| D{needsActivities?}
  C --> C1[(save plan result)]
  C1 --> D
  D -->|yes| E[pendingActivityBriefs only]
  D -->|no| H{needsCourseContent?}
  E --> F[parallel generate missing/failed stale activities]
  F --> G[(save each completed activity)]
  G --> H
  H -->|yes| I{playable coverage gate}
  H -->|no| K[return existing draft]
  I -->|pass| J[runCourseContentPhase]
  I -->|fail| L[stop before content]
  J --> M[(save course content)]
Check Meaning Effect
needsLearningPlan No activity plan exists, or caller forces regeneration. Runs only the planning Ax flow and saves plan before any activity work.
pendingActivityBriefs Compares current briefs against saved generated activities by briefId. Resumes by generating only missing or stale activity packs.
hasPlayableGeneratedActivityCoverage Every brief must have a current playable generated activity. Course content cannot run until the reusable activity phase has real coverage.
needsCourseContent Course content is empty or stale. Rendering runs after activity coverage, otherwise existing content is reused.

Failure paths

flowchart TD
  A[Phase starts] --> B{Which phase fails?}
  B -->|Planning Ax error| C[(save learning_blueprint_generation failed)]
  C --> D[stop; no activity/content phase]
  B -->|Single activity Ax error| E[failedActivityFromBrief]
  E --> F[(save not_playable activity for that brief)]
  F --> G[continue remaining briefs]
  G --> H{coverage complete?}
  H -->|only playable current coverage| I[allow content phase]
  H -->|any failed/not_playable| J[block content; artifacts retained]
  B -->|Content Ax/render error| K[(save course_content_generation failed)]
  K --> L[keep saved plan and generated activities]
  B -->|Full-auto child phase fails| M[(parent course_generation failed)]
  M --> N[latest phase artifacts stay saved for resume]
Important: failed activity generation is persisted as a failed activity result for that exact brief. The renderer does not invent a fallback section from the title, chunk name, filename, or old route language.

Source of truth in code

Area File Responsibility
Ax planning flow server/coursition/ai-provider.ts coursitionActivityGenerationFlow returns outputLanguage, preparation, objectives, and briefs only.
Ax reusable activity flow server/coursition/ai-provider.ts coursitionPlayableActivityFlow writes and judges one playable activity pack from one brief.
Provider exports server/coursition/ai-provider.ts generateLearningPlanWithAi and generateActivityWithAi are separate phase entry points.
Persistence orchestration server/coursition/store.ts runLearningPlanPhase, runActivityPhase, and runCourseContentPhase save after each phase.
Full-auto call chain server/coursition/store.ts generateCourse calls planning, activity, then content in order; parent run fails if a later gate blocks.
Semi-auto call chain src/features/coursition/coursition-workflow-app.tsx The activity plan button sends generateActivities, which reaches the same store/provider path as full-auto.
Gates and API schema shared/coursition/workflow.ts, shared/api.ts activity_generation and generateActivities are first-class workflow concepts.

Precise phase contract

  • Phase 1 stores only planning artifacts: course preparation, objective map, activity briefs, and chosen output language.
  • Phase 2 stores generated activities one by one, as soon as each Ax call finishes.
  • Phase 3 renders course content only from saved generated activities.
  • Full-auto and semi-auto differ only by who triggers the phases; the activity generator is identical.
  • Resume is based on persisted draft state, not on in-memory progress.
  • No old schema branch, compatibility shim, local language regex, or title-based fallback is part of the contract.
